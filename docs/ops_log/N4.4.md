## Note for P15A.2 when the lane runs on the MBP (N14)

P15A.2's guard refuses localhost, 127.0.0.1, ::1 and port 15432 unless `HOME_LANE_ALLOW_LOCAL=1`
(REMEDIATION :3489). That list was written for the mini. On the MBP, the DSN in `.env` has no
host in its netloc. It reaches local `cars` through the Unix socket in `/tmp`, given as the
`host` query parameter (`docs/SCANNING_OPS_LOG.md:1246`). A guard built from the REMEDIATION
text that compares only the URL hostname would read `None` for that DSN and would not refuse
it. On the MBP the guard must also refuse a DSN with an empty hostname or with a `host`
parameter that is a socket path (it starts with `/`), and the libpq keyword form
(`host=/tmp dbname=cars`), unless `HOME_LANE_ALLOW_LOCAL=1`. P15A.2's tests should include
these DSNs.

## The rule "the mini does not scan until P1C is done"

**Status:** it holds for everything that can be seen from the MBP. The mini itself is
cannot_assess, because nothing on it was read.

The N4.4 agent ran these read-only checks on the MBP on 2026-10-18 at about 18:25Z. SQL used
`PGOPTIONS='-c default_transaction_read_only=on -c statement_timeout=120000' psql -X -h /tmp -p 5432 -d cars -Atc ...`,
and `SHOW default_transaction_read_only` printed `on`. The listener, process, SSH, session and
Tailscale rows are a snapshot at that time. The `cars` and `scan_runs` rows cover the whole
period since 2026-10-08.

| Check | Result | What it shows |
|---|---|---|

The checks above show that no scan has written local `cars` since 2026-09-28.

These need SSH, or the owner at the mini, and stay cannot_assess:

The P0A.5 pack (read-only except one unload line) answers the first point on the mini.

## What N4.3 needs from this unit

N4.3 retires `feature/http-only-scans` "after N4.4's mini check or waiver" (NEXT_PHASES :920).
REMEDIATION :1085 asks for `git status` and `git log @{u}..` on the mini's clone. Under (b) that
check was not run. This record is not a waiver, because a waiver is the owner's decision. There
are two ways to unblock N4.3:

1. The owner runs these read-only commands on the mini and pastes the output into a dated block
   at the end of this file:
   ```
   cd <mini checkout> && git status --short --branch && git log --oneline --branches --not --remotes && git stash list
   ```
   There is no unpushed work if the status is clean and both lists are empty. `--branches --not
   --remotes` covers every local branch, not only the checked-out one.
2. The owner logs a waiver row in `OWNER_DECISIONS_LOG.md`.

One fact matters for that choice. Deleting the remote branch does not delete any commit in the
mini's clone. Those commits stay on its local branch, whose upstream then shows as gone, and
they can still be pushed to a new branch. D-REL4 (a) also tags `archive/*` before any delete.

The mini returns only through option (a) of this unit. That needs SSH approval, or the owner

   release commit.
6. Install Tailscale on the mini, log it in, and enable Remote Login (OPS-6).
7. Every mini command prefixes `INVENTORY_DATABASE_URL=postgresql://localhost:15432/cars` and
   prints the DSN's `host` before any write. The mini's `.env` points at its own Postgres, and
   668 rows went to the wrong DB on 09-26.

   which were settled only by implication from (b). The re-plans above then revert: P6A.7 and
