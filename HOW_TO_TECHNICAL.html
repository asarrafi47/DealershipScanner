System Overview

Sarrafi Collection is a sophisticated dealership intelligence platform that:

  • 🚗 Crawls dealership websites and OEM platforms to discover and ingest vehicle listings
  • 📊 Enriches raw listing data with EPA specs, market intelligence, and semantic embeddings
  • 🔍 Provides hybrid search (SQL + pgvector semantic search) to users
  • 💳 Manages user subscriptions and feature access via a billing system
  • 📱 Serves web and mobile (iOS) interfaces for end users
  • 🏢 Includes admin dashboards for dealers and platform operators
Core Tech Stack:
  • Backend: Flask (Python) + async scanner (Node.js/Crawl4AI)
  • Databases: SQLite (local dev), PostgreSQL (production), pgvector (embeddings)
  • Frontend: Jinja2 templates, JavaScript (interactive features)
  • Mobile: SwiftUI (iOS)
  • AI/ML: OpenAI embeddings, Claude API for intelligent features
  • Authentication: OAuth 2.0 (Google, Apple), MFA support
  • Deployment: Railway, Docker, Cloud infrastructure

EPA Knowledge Engine

The EPA engine is the brain of enrichment. It uses vehicle specs (year, make, model, trim) to look up detailed EPA data:

EPA Lookup Process:
  1. Parse vehicle trim from listing (e.g., "2024 BMW i7 xDrive50")
  2. Match against EPA master index (database table)
  3. Retrieve MPG, CO2, fuel type, engine specs
  4. Generate window sticker (MSRP, ratings)
  5. Cache results for 30 days

Image Analysis (Vision Module)

Extracts features from dealer photos:

  • Detect condition indicators (scratches, dents, cleanliness)
  • Identify interior/exterior colors (verify against metadata)
  • Extract text (license plates, odometer for mileage hints)
  • Filter low-quality or irrelevant images

Embedding Generation

Raw listing text is converted to embeddings using OpenAI's API:

# backend/vector/embeddings.py def generate_listing_embedding(listing: dict) -> np.array: # Build text: title + description + specs + features text = f"{listing['title']} {listing['description']} {listing['specs']}" # Call OpenAI API response = openai.Embedding.create( input=text, model="text-embedding-3-small", # 1536 dimensions dimensions=1536 ) # Returns 1536-dimensional vector # Stored in pgvector table for similarity search
💡 Embeddings: Convert text into numerical vectors that capture semantic meaning. Similar vehicles (e.g., "red sports car" and "red sports sedan") have similar embeddings, enabling intelligent search without exact keyword matching.

How pgvector Works

PostgreSQL extension that stores and queries vectors (embeddings):

-- Create pgvector extension (one-time setup) CREATE EXTENSION IF NOT EXISTS vector; -- Listings table with embedding column CREATE TABLE listings ( id BIGINT PRIMARY KEY, vin VARCHAR UNIQUE, title VARCHAR, price DECIMAL, year INTEGER, make VARCHAR, model VARCHAR, embedding vector(1536), -- 1536-dim OpenAI embedding created_at TIMESTAMP ); -- Create HNSW index for fast similarity search CREATE INDEX ON listings USING hnsw (embedding vector_cosine_ops) WITH (m = 16, ef_construction = 64); -- Similarity search query SELECT id, title, price, (embedding <-> query_embedding) AS distance FROM listings WHERE (embedding <-> query_embedding) < 0.5 -- similarity threshold ORDER BY embedding <-> query_embedding LIMIT 20;

  • Application logs: Flask request logs, error tracking (Sentry)
  • Scanner logs: Discovery, crawl, parse success/failure rates
  • Database metrics: Connection pool utilization, query performance
  • Uptime: Alerting on service failures
  • Cost tracking: OpenAI API usage, AWS/Railway bills

Development Workflow

Branching & Git Strategy

The project follows a feature-branch workflow:

# Create feature branch git checkout -b feature/my-feature # Make changes, commit often git add . git commit -m "Clear commit message" # Push and create pull request git push origin feature/my-feature # Open PR on GitHub for review # After approval, merge to main # (CI/CD runs tests automatically)

Running Tests

# Run all tests pytest backend/tests/ -v # Run specific test file pytest backend/tests/test_enrichment.py # Run with coverage pytest backend/tests/ --cov=backend --cov-report=html # Run scanner tests only pytest backend/tests/test_scanner*.py

Common Development Tasks

Task Command Notes
Start Flask dev server flask --app backend.main run Watches for changes, auto-reloads
Run scanner locally python scanner.py --scan-only Uses INVENTORY_DB_PATH (SQLite)
Trigger post-processing python post_scan.py --enrich-only Enrichment without crawl
Reset local database rm *.db && python scanner.py --scan-only Full fresh start
Build trim ladders python -m backend.scripts.build_trim_ladders Regenerate after dict updates
Reindex vectors python backend/scripts/reindex_vectors.py Requires PGVECTOR_URL (Postgres)
💡 Development Tips:
  • Use PYTHONPATH=. flask --app backend.main run to ensure imports work
  • SQLite is perfect for local development—no DB setup needed
  • For Postgres features (pgvector), run a local Postgres instance or use a managed service
  • Check backend/config/ for environment-specific settings

Debugging Tips

# Enable Flask debug mode export FLASK_DEBUG=1 # Verbose logging export DEBUG=1 # Inspect database sqlite3 inventory.db "SELECT * FROM listings LIMIT 5;" # Check recent logs tail -f /tmp/scanner.log # Profile a specific function python -m cProfile -s cumtime script.py # Interactive debugging python -m pdb script.py # breakpoint() in code

Code Organization Best Practices

  • Modules: Each major feature gets its own directory (auth/, billing/, scanner/)
  • Naming: Functions and variables use snake_case; classes use PascalCase
  • Database: SQL queries in db.py, business logic in service.py
  • Error handling: Use custom exceptions (backend/utils/exceptions.py)
  • Tests: Place alongside production code in tests/ subdirectories
  • Documentation: README.md per module, docstrings for public APIs
